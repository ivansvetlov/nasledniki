# Пайплайн карты районов

> Зафиксировано 2026-08-14. Это контракт: что считается готовым результатом
> и как к нему приходить **без ручного Paint**.
>
> Актуальный рабочий контур (OSM + редактор швов, 2026-08-20):
> `docs/MAP-EDITOR.md`. Этот файл — стиль и запрет Paint.

## Принятый результат

Эталон визуала: `prototype/map-fills-only.svg`.

- Подложка один цвет (`#F2E8D5`).
- Каждый район — **один** замкнутый `<path>` со своей заливкой.
- **Никакого `stroke`.** Между районами видна подложка (щель = бывшая граница).
- Слоя `#borders` нет и не будет.

Так выглядит политическая карта, с которой дальше удобно работать
(Figma / Inkscape / клики на сайте). Чёрная обводка `#2B2317` /
`rgb(43, 35, 23)` — ошибка предыдущих итераций, не часть продукта.

## Вход

Единственный вход пайплайна:

`reference/samara-oblast-map.jpg`

Монохромная карта районов Самарской области из интернета (633×777):
светлые заливки районов, тёмные линии границ, точки райцентров, подписи
внутри и снаружи. Ручная дорисовка поверх **не требуется**.

`reference/paint-editable/` — архив обходного пути (см. ниже), не вход.

## Как описан район (модель данных)

Не «массив точек в RGB». Два слоя, разные задачи:

| Слой | Что хранит | Зачем |
|---|---|---|
| Растр (пока считает скрипт) | `label[y, x] = id` района | Нарезка из JPG. Пиксель либо район, либо щель. |
| SVG (то, что правим) | полигон: список вершин `(x, y)` + один `fill` на весь path | Редактор, клики, сайт |

Граница — это рёбра полигона (от точки к точке), не цвет. RGB/hex — атрибут заливки, у всех вершин района один.

Три модели, разный оптимум:

1. **Независимые полигоны** (сейчас в SVG). Просто править в Figma, один объект = один район. Соседние районы **не делят** ребро: сдвинул вершину — щель или нахлёст. Для нашего визуала (щель = подложка) это как раз то, что нужно.
2. **Топология** (DCEL / TopoJSON): общее ребро хранится один раз. Математически правильная админкарта, без щелей. В Figma так не редактируется. Имеет смысл, если позже понадобится «сшивка» без зазоров.
3. **Растр меток**: оптимален как *промежуточный* расчёт из картинки. В редактор и на сайт его не отдаём.

Итого для этого проекта: считать растром, отдавать независимыми полигонами без stroke. Это не компромисс «на глаз», а правильная пара моделей под задачу.

## Почему Paint вообще появился (чтобы не повторять)

1. `trace-map.py` взял все светлые пиксели как **одну** маску и снял
   внешний контур → одна клякса, районы не нарезались.
2. Дальше агент боролся с текстом, точками городов и тёмной заливкой
   Елховки (серый район принимали за границу).
3. Владелец обвёл границы пожирнее в Paint (`1-borders.png`), чтобы
   связные компоненты чёрных ячеек стали 25 районами.
4. Следующие коммиты (`5ab608c`…`41ab386`) рисовали **второй слой** —
   скелет / полилинии / фильтр полосок. Заливки из шага 3 были верными;
   чёрный слой — нет.

Paint компенсировал две вещи, которые должен делать скрипт:

| Руками в Paint | Автоматом |
|---|---|
| Убрать подписи и точки, чтобы они не рвали район | inpaint компактных тёмных пятен (точки) и мелкого текста |
| Нарисовать линии пожирнее, чтобы закрыть разрывы | слегка утолстить **только линии** (не серые заливки) |

Серую Елховку нельзя считать границей: граница — тонкая тёмная **линия**,
заливка — компактная область любой яркости внутри контура.

## Целевой алгоритм (замена Paint)

1. Серый JPG → маска территории (не белый фон, largest external contour).
2. Внутри территории найти и закрасить (inpaint):
   - точки городов: тёмные компактные пятна, площадь ~8–300 px;
   - подписи: мелкие вытянутые тёмные компоненты / MSER.
3. Оставшиеся тёмные пиксели классифицировать по геометрии:
   тонкая линия = граница; компактная область = район (даже если серый).
4. Линии чуть закрыть (`dilate` 2–3 px) — это и есть «пожирнее в Paint».
5. Ячейки = территория минус утолщённые линии → `connectedComponents`.
   Выкинуть внешность и мусор `< 300` px.
6. У каждого района контур (`approxPolyDP` в **пикселях**, ~1–1.5 px,
   не 0.3% периметра). Без сглаживания, которое раздувает кляксу.
7. SVG: `<rect>` подложки + `<g id="regions">` из path **только с fill**.

Параллельный источник геометрии (не вместо этого пайплайна, а рядом):
OpenStreetMap уже содержит те же районы как полигоны с именами.
Разбор: `docs/OSM-QGIS.md`. Для сайта экспедиций это, скорее всего,
лучший канон формы; JPG остаётся референсом стиля (заливка, щели).

Ожидаем ~27 районов по подписям на исходнике. В эталоне сейчас 25 —
два района слиплись из‑за дырки в нарисованной границе. Автопайплайн
должен стремиться к 27, не копировать 25.

## Что не делать

- Не трассировать скелет и не класть слой `#borders`.
- Не фильтровать «полоски» по числу соседей — слоя линий нет.
- Не просить владельца обводить карту в Paint.
- Не считать `map-final.svg` с обводкой успехом.

## Критерий готовности пайплайна

Команда (одно действие):

```
C:\Workspace\_agent\.venv\Scripts\python.exe scripts\make-svg.py
```

берёт только `reference/samara-oblast-map.jpg` и перезаписывает
`prototype/map-fills-only.svg`.

Готово, если:

- в SVG нет `stroke` и нет `#borders`;
- районов 25–27, каждый — один path;
- визуально как эталон: цветные пятна, между ними подложка, чёрного нет;
- повторный прогон даёт тот же файл (детерминированно).
