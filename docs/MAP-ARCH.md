# Архитектура: мастерская карты → продукты

Зафиксировано как решение, не как бэклог «потом подумаем».
Редактор — цех геометрии. Сайт «НаСЛЕДНИКИ» и любой другой продукт —
потребители **опубликованного снимка**, не живой сессии Figma-like редактора.

Два разных артефакта, которые уже есть и их нельзя смешивать:

| | Мастерская сейчас | Прототип сайта `prototype/map.html` |
|---|---|---|
| Что | 27 районов OSM, щель = подложка | 4 макрозоны, Безье, штриховка, пины, маршруты |
| Стиль | пастель, без stroke | журнал: terra, hatch, Oswald |
| Данные | `path[data-name]` + `fill` внутри SVG | декоративная сцена «как в журнале» |

Стилизация сайта **натягивается на геометрию цеха**. Художественный `map.html`
не заменяет 27 тел — это оверлей/тема, не другой кадастр.

---

## Три слоя (не два)

```
① Геометрия     канон: id, имя, контур, щель, viewBox
② Тема          как рисовать: цвета, штрих, бумага, hover
③ Продукт       что поверх: экспедиции, «открыл/не открыл», вырезка зон
```

Сейчас ① и ② слиты: `fill="#EAD9BC"` торчит в `map.svg`. Из‑за этого
«другой стиль» = править SVG руками. Правило дальше: **контур без вкуса продукта**.
`fill` в файле цеха — дефолт темы `atlas-plain`, не контракт сайта.

```
мастерская (write)                    продукты (read)
┌─────────────────────┐              ┌──────────────────────────┐
│ OSM / шов / слои    │  publish     │ НаСЛЕДНИКИ /map          │
│ аккаунт, проекты    │ ──────────►  │ кабинет «карта поездок»  │
│ живой SVG сессии    │  snapshot    │ другой бренд позже       │
└─────────────────────┘              └──────────────────────────┘
         │                                      ▲
         │  GET /v1/maps/{id}?theme=…           │
         │  GET /v1/maps/{id}/zones?ids=…       │
         └──────────────────────────────────────┘
```

Эндпоинты мастерской — **да**, но не те, что крутят нож и Overpass.
Два лица одного сервера (можно два префикса, один процесс на старте):

| Лицо | Кто зовёт | Примеры |
|---|---|---|
| **Workshop** (сессия) | редактор | `/api/maps` create/load/save, `/api/search`, аккаунт |
| **Publish** (снимки) | сайт, другой проект | `/v1/maps/samara`, `…/svg?theme=nasedniki`, `…/zones?ids=` |

Сайт не ходит в Nominatim и не открывает `map-bench.html` в iframe.

## Канон геометрии (что публикуем)

Один объект «карта» = стабильный `id` (slug) + версия снимка.

Зона:

```
id            syzran          стабильный, не подпись из OSM
name          Сызранский район
kind          district | city | water | overlay
path          d="M…" в координатах viewBox карты
fill_group    west | default  опционально, для темы
```

Карта:

```
id            samara
version       3                 номер публикации, не git
viewBox       0 0 W H
gap_px        3
crs           svg-local         позже: ещё wgs84, если понадобятся пины по lat/lon
zones[]
```

Растр `labels[]` и стек слоёв редактора **наружу не отдаём**.
Слои «текст / штрих» — черновик цеха; в продукт попадает только то,
что пометили к публикации (по умолчанию — районы).

Версия: продукт держит `samara@3`. Пока не обновил ссылку — старый шов.
Публикация = кнопка в цехе «выпустить», не каждый Ctrl+S.

## Темы (стилизация без новой нарезки)

Тема — CSS + опциональный словарь заливок. Геометрия та же.

| Тема | Кто | Как выглядит |
|---|---|---|
| `atlas-plain` | цех, Figma-экспорт | как сейчас: `#F2E8D5`, пастель, без stroke |
| `nasedniki-journal` | сайт | бумага, sage/gold, hover terra, можно hatch; **не** чёрный stroke внутри тел |
| позже | другой продукт | свои токены |

Натянуть стиль = не пересобирать OSM. Рендер:

```
geometry.zones[].path  +  theme.paint(zone)  →  SVG или Canvas
```

`prototype/map.html` почти эта схема, только path'и там рисованные, не из цеха.
Следующий шаг сайта: подставить 27 `d` из publish API, оставить штриховку/пины/маршруты
как **оверлей темы и продукта**.

Правило щели не ломаем в темах продукта: обводка — hover/selected, не граница кадастра.

## Вырезка «часть карты в свой проект»

Не форк всего SVG, а **ссылка + фильтр**.

Продукт хранит:

```
map_ref:
  source:  workshop:samara@3
  theme:   nasedniki-journal
  include: [syzran, stavropol, volzhsky]   # или all
  overlay: expeditions | opened_cities
```

Эндпоинт:

```
GET /v1/maps/samara?version=3&theme=nasedniki-journal&ids=syzran,volzhsky
GET /v1/maps/samara.svg?...     готовый SVG для <img> / вставки
GET /v1/maps/samara.json        зоны + viewBox, фронт рисует сам
```

Три потребителя:

1. **Карта открытий кабинета** — вся Самара, тема журнала, сверху пины
   из API кабинета (открыл / не открыл). Геометрия из цеха, стейт — из продукта.
2. **Карточка экспедиции «Сызрань»** — `ids=syzran` (+ сосед, если нужен контекст).
3. **Чужой бренд** — тот же `samara@3`, другая `theme`, другой overlay.

Копировать SVG в репозиторий сайта можно как **заморозку** на деплой
(офлайн, без мастерской). Канон всё равно версия в цехе, не копия навсегда
без номера.

---

## Почему не «просто отдать текущий map.svg»

- В нём запечён `fill` цеха — тема сайта не натягивается чисто.
- `data-name` с OSM («Сызранский район») ≠ id продукта (`syzran`).
- Живой файл аккаунта Ivan меняется ножом — сайт не должен плыть без публикации.
- Слои/текст редактора не обязаны ехать на лендинг.

## Контракт API (сделано)

Один процесс `map_server.py`. Чтение публичных снимков **без логина**.

Мастерская (как раньше): `/api/…` cookie.

Publish:

```
GET  /v1/maps
GET  /v1/maps/samara
GET  /v1/maps/samara/geometry
GET  /v1/maps/samara.svg?theme=nasedniki-flow&ids=syzran,volzhsky
GET  /v1/themes
GET  /v1/themes/nasedniki-flow
POST /v1/maps/{id}/publish     { "slug": "samara" }  — снимок из проекта аккаунта
```

НаСЛЕДНИКИ (натягивает тему на снимок):

```
GET /nasedniki/map                 страница
GET /nasedniki/api/map?style=nasedniki-flow&ids=syzran
GET /nasedniki/api/map.svg?style=nasedniki-journal
```

Темы витрины: `atlas-plain` (цех), `nasedniki-journal` (бумага), `nasedniki-flow`
(сильное Chaikin-обтекание). Геометрия цеха не переписывается.

Самара публикуется при старте сервера, если снимка ещё нет.

## Что делать по шагам, когда вернёмся к сайту

1. Стабильные `id` зон Самары (латиница) рядом с `data-name`.
2. Тема `nasedniki-journal` как CSS на те же path — проверить на 27 телах,
   не на 4 макрозонах.
3. `GET …/geometry` + страница `/map` сайта подставляет path из снимка,
   пины экспедиций — свои.
4. Вырезка по `ids` для карточки одной экспедиции.
5. Кнопка «опубликовать» в цехе, сайт указывает `samara@N`.

До этого редактор можно не трогать: геометрия Самары уже годится как источник.
Не тащить аккаунты цеха и Overpass в бэкенд «Наследников».
