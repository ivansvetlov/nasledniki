# «НаСЛЕДНИКИ» — анализ ТЗ и план реализации

> Проект: познавательно-экспедиционный сайт для детей 10–17 лет, Самарская область.
> Организатор: ООО «Кинокомпания Медиа-С».
> Этот документ — разбор слабых мест исходного ТЗ, улучшения и полный список
> того, что нужно для реализации сайта «уровня экспедиционного журнала».

## 0. Вывод по ТЗ одним абзацем

Исходное ТЗ — **хорошая философская основа и грамотная механика личного кабинета**,
но как техническое задание оно «худое»: нет структуры, ролей и прав, нет модели
данных, нет целей/метрик, нет техстека, нет бюджета на иллюстрации, визуальная
концепция описана ссылками на чужие сайты без своего языка. Пункты 13–18 (кабинет)
написаны вперемешку с общими словами («далее остается вся механика, которую мы
прописали»), а пункты «Мои достижения / монеты / карта / викторина» — вообще без
технических требований. Слабые места ниже.

## 1. Разбор слабых мест (критично → косметика)

### 1.1 Критичные — без них проект не реализуем

| # | Слабое место | Почему критично | Что исправить |
|---|---|---|---|
| K1 | **Нет технической архитектуры и стека** | ТЗ описывает только «что», ни слова «на чём». Кабинет с ПДн детей, заявками, файлами, монетами и викториной — это полноценный бэкенд + БД + авторизация, а не лендинг. | Зафиксировать стек (предложение в §4), модель данных, роли. |
| K2 | **Работа с ПДн несовершеннолетних описана декларативно** | «Защищённое хранение» — без конкретики. Это риск 152-ФЗ, уголовная ответственность при утечке. Документы детей (серия/номер паспорта) — это биометрически-чувствительная категория. | Технические меры: шифрование в БД, RBAC, журнал доступа, минимальный сбор (минимизация), сроки хранения, DPA. |
| K3 | **Нет ролей и разграничения прав** | Упоминаются родитель, ребёнок, администратор — но не описано кто что видит. Например: видит ли ребёнок телефон родителя? Видит ли родитель журнал ребёнка? | Матрица ролей (таблица в §4). |
| K4 | **Согласия (фото/видео, ПДн, участие) только перечислены** | Нет юридического модуля: типы согласий, версии документов, срок действия, кто подписывал, где хранится факт подписания. | Модуль согласий с версионированием и журналом. |
| K5 | **«Регистрация через родителя» не продумана** | Не описано: как ребёнок потом логинится, один аккаунт на семью или раздельные, что с детьми без мессенджера, верификация телефона. | Модель аккаунтов: семейная (1 родитель → N детей), ребёнок логинится через родительский аккаунт или отдельный профиль с привязкой. |
| K6 | **Нет целей, метрик и критериев приёмки** | Нет ответа «как понять, что сайт хороший». Конверсия заявок? Время до первой записи? | KPI: конверсия лид→заявка, время регистрации, % родителей завершивших профиль, N детей с журналом после 1 поездки. |

### 1.2 Значимые — качество реализации

| # | Слабое место | Исправление |
|---|---|---|
| V1 | **Визуальный язык не свой, а «три референса»** | Национальная География + Polar Light + Hedonism Club — разнонаправленные. Нужен свой коннепт-борд и дизайн-токены (палитра, шрифты, иллюстрации). |
| V2 | **Ограничение по фото детей не превращено в дизайн-возможность** | «Нет фото детей» — это плюс: позволяет строить подачу через иллюстрации, маскоты, 3D-локации, изометрия, карты. Именно здесь понадобятся иллюстраторы (см. §5). |
| V3 | **Механика монет/уровней/достижений не специфицирована** | Нет: сколько монет за что, чем отличается уровень, как работают достижения, что происходит при сгорании/возвратах. |
| V4 | **Викторина описана идеей, а не продуктом** | Нет: банк вопросов, типов вопросов, анти-чит (возраст?), наград, повторного прохождения, фильтра по маршруту. |
| V5 | **Карта открытий без данных** | Нужны геоданные Самарской области, маркеры, координаты, фото. |
| V6 | **Журнал Наследника без форматов** | Текст + фото + ссылка на пост + оценка — не хватает: медиатека, модерация (контент детей!), безопасность модерации. |
| V7 | **Уведомления только перечислены** | Не указан канал (SMS/Telegram/email/push), шаблоны, расписание («за 5 дней», «за 1 день»). |

### 1.3 Косметика — «нейрослоп» в тексте

- ❌ Обороты «далее остается вся механика, которую мы прописали», «Мне вообще нравится сделать ее как будто это новая миссия», «Не отдельный документ. А красивую страницу» — заменить на требования.
- ❌ Путаница нумерации: «ЭТАП 5» обрывается, дальше идут «14. Журнал», потом «4. Мои достижения», «5. Мои монеты» — нумерация сломана.
- ❌ «Справка в ГИБДД» в блоке документов — странно, скорее опечатка / не тот документ.
- ❌ Дубли: «Личный кабинет» описан дважды (13 и после 18), «достижения» дважды.
- ❌ Нет явной карты сайта (sitemap) с URL-структурой.

## 4. Предлагаемый технический стек

> Наш стек по умолчанию (конституция Workspace): FastAPI + Postgres + Redis + RQ/Celery.
> Фронт — React/TS (SPA) или HTML/JS для лендинга с кабинетом.

| Слой | Стек | Почему |
|---|---|---|
| Бэкенд | **FastAPI** (Python) | Быстро, типизировано, асинхронно, наш стандарт |
| БД | **PostgreSQL** | Реляционная: участники, заявки, журналы, монеты, викторины, согласия. JSONB для гибкости. |
| Кэш/очереди | **Redis + RQ/Celery** | Уведомления «за 5 дней», генерация PDF списков, рассылки |
| Авторизация | JWT (access+refresh), роли: parent / child / admin | Раздельные профили |
| Файлы/медиа | S3-совместимое (или локальный диск + nginx) | Фото в журнале, загруженные документы |
| Фронт | React/TS + Vite; GSAP для интерактивов | Наши бенч-паттерны (interactive sites) |
| 3D/интерактив | Three.js / R3F (сцены локаций), Canvas (эффекты) | «Экспедиционный журнал» живёт анимациями |
| Медиа-генерация | Higgsfield / Google Flow для ассетов; иллюстратор — ключевые 2D | §5 |
| PDF/Excel | reportlab / openpyxl | Списки участников, документы, памятки |
| Уведомления | Telegram Bot API + SMS-шлюз + email (шаблоны Jinja) | Родитель выбирает канал |
| Аналитика | Яндекс.Метрика / Plausible | KPI |

### Модель данных (ядро)

- `users` (роль, контакты, верификация)
- `families` (родитель ↔ дети)
- `children` (ФИО, дата рождения, школа, класс, город; связь с users через families)
- `child_documents` (тип: св-во/паспорт; серия, номер, дата, кем выдан — **шифровано**)
- `expeditions` (slug, город, название, даты, программа, локации, цены, места)
- `applications` (заявка: expedition_id, child_id, статус, роль)
- `consents` (тип, версия, child_id, signed_at, подписант) — версии документов
- `journal_entries` (глава: expedition, текст, фото, ссылка, оценка, монеты)
- `quiz_questions` / `quiz_results` (банк вопросов по маршрутам, попытки, награды)
- `transactions` (монеты: начисление/списание, причина)
- `achievements` / `user_achievements` (ачивки и выдача)
- `notifications` (шаблон, канал, расписание, статус доставки)

|---|---|---|---|

## 5. Что нужно для реализации «уровня журнала» (полный список)

### 5.1 Арт-продакшн (иллюстраторы + генерация)

Сайт «без фото детей» обязан быть построен на **своём визуальном мире**.
Минимум для уровня «экспедиционный журнал»:

1. **Концепт-борд и дизайн-токены** — палитра (терра-коричневый/хаки/карта/крем,
   отсылка к картам и старой бумаге), шрифты (заголовки — геометрия/брутализм,
   текст — читаемый), текстуры (бумага, карта, штампы).
2. **Маскот / талисман проекта** — животное Самарской Луки (напр. суслик, беркут,
   рысь) в 3-4 позах (приветствие, исследование, фото, находка). Это «лицо» проекта.
3. **Иллюстрации 4 локаций** (Сызрань, Тольятти, Жигулевск, Самара):
   - изометрическая карта каждой локации с ключевыми точками (кремль, штольни, лодка);
   - 3-5 атмосферных сцен сюжетно (поезд, дорога, лагерь у Волги);
   - паттерны/орнаменты (для фонов, разделителей, штампов-ачивок).
4. **Иконки-«предметы экспедиции»**: компас, блокнот, фотоаппарат, билет, рюкзак,
   поезд, карта — единый стиль (вырубленные/штампованные).
5. **Набор ачивок** (Первое открытие, Лучший кадр, Первое интервью, Исследователь
   региона, Активный Наследник) — как нашивки/медали.
6. **3D-сцены локаций** (three.js) — для первого экрана/карты; можно генерить
   ассеты в Higgsfield/Hunyuan 3D + доработка в Blender, НО ключевые герои/карта —
   руками иллюстратора.

**Сколько арт-работ:** ~40–60 единиц (концепт + 4 локации + маскот + иконки +
ачивки + паттерны). Реалистично: 3–6 недель иллюстратору (полная занятость) или
2–3 иллюстратора параллельно. Часть (фоны, вариации, 3D-превью) — генерация
Higgsfield/Google Flow + ретушь, чтобы снизить ручной объём до ~30–40%.

### 5.2 Дизайн UI/UX

- Интерактивный прототип кабинета (Figma): родительский флоу (регистрация → ребёнок → документы → заявка → чек-лист) и детский (журнал → викторина → карта).
- Дизайн-система (токены, кнопки, формы, статусы, карточки экспедиций).
- Адаптив mobile-first (родители сидят с телефона).
- Микроанимации (наш бенч!): тосты, счётчики монет, карта открытий, роли.

### 5.3 Бэкенд/данные

- Модель данных (§4), миграции (Alembic).
- Auth + RBAC (роли parent/child/admin), верификация телефона.
- Модуль ПДн: шифрование документов, журнал доступа, согласия с версиями, минимизация.
- API для кабинета, заявок, журнала, монет, ачивок, викторины, карты.
- Админка (списки групп, выгрузка Excel/PDF, рассылка уведомлений, начисление монет).
- Уведомления (Telegram/SMS/email, расписания, шаблоны).

### 5.4 Юридика (обязательно до запуска)

- Политика обработки ПДн (152-ФЗ), уведомление Роскомнадзора.
- Согласия: на обработку ПДн, на участие, на фото/видео (отдельно).
- Договор-оферта, правила проекта.
- DPA с подрядчиками/хостингом (если не своя инфраструктура).

### 5.5 Контент

- Тексты под позиционирование («экспедиция», а не «тур»).
- Описания 4 экспедиций: программа, маршрут, что увидят, роль, снаряжение.
- Банк вопросов викторины по каждому маршруту (10–20 вопросов × 4 = 40–80).
- FAQ для родителей, памятки, список вещей (PDF).
- Материалы кинопроекта (трейлер/эпизоды) — если есть.

### 5.6 Деплой/инфраструктура

- VPS/хостинг с сертификатом (Timeweb у нас уже в обороте), домен.
- HTTPS, бэкапы, мониторинг.
- CI/CD (GitHub Actions → Docker → сервер) — паттерн как у flowwow.

## 6. Этапы реализации (дорожная карта)

| Этап | Содержание | Результат | Оценка |
|---|---|---|---|
| 1. Спецификация | Утвердить стек, модель данных, матрицу ролей, согласия | ТЗ v2, ER-модель, схемы флоу | 3–5 дней |
| 2. Дизайн-концепт | Концепт-борд, маскот, 4 локации, токены, прототип кабинета | Figma-набор | 2–4 недели (параллельно с арт) |
| 3. Арт-продакшн | Иллюстрации, иконки, ачивки, паттерны, 3D-сцены | Библиотека ассетов | 3–6 недель |
| 4. Backend MVP | Auth/RBAC, кабинет, заявки, документы, админка | API + админ | 3–4 недели |
| 5. Frontend MVP | Лендинг + кабинет + карта + журнал | Сайт в проде | 3–4 недели |
| 6. Геймификация | Монеты, ачивки, викторина, карта открытий | Полная механика | 1–2 недели |
| 7. Юридика + тест | Согласия, политика, приёмка, перфоманс | Запуск | 1–2 недели |

**Итого реалистично: 2.5–4 месяца** (арт-продакшн — критический путь).
